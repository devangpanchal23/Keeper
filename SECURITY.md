# Security Policy for Keeper

We take the security of Keeper and the privacy of its users seriously. If you believe you have discovered a security vulnerability, we appreciate your help in responsibly disclosing it to us.

---

## Supported Versions

| Version / Branch | Supported |
| :--- | :---: |
| `open_source_keeper` | :white_check_mark: |
| `main` | :white_check_mark: |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, report them privately using GitHub Private Vulnerability Reporting or by contacting the project maintainers directly.

### What to Include
When reporting a vulnerability, please provide as much context as possible:
1. **Type of issue**: (e.g., SSRF, XSS, Authentication bypass, IDOR, SQL injection).
2. **Location**: Specific API routes, components, or files affected.
3. **Step-by-step reproduction instructions**: A clear description or proof-of-concept (PoC) showing how the issue can be reproduced.
4. **Impact**: Potential consequences if exploited.
5. **Remediation**: Suggested fixes or mitigations, if known.

---

## Vulnerability Handling Process

1. **Acknowledgment**: We will acknowledge receipt of your report within 48 hours.
2. **Investigation**: We will verify the vulnerability and evaluate its severity.
3. **Remediation**: We will prepare a patch and validate it through automated regression tests.
4. **Disclosure**: Once patched, a security release will be published along with appropriate credit to the reporter.
