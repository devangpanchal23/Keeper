# Keeper Phase 0 — Risk Register

| ID | Severity | Risk | Evidence / impact | Recommended mitigation |
|---|---|---|---|---|
| R1 | Critical | Predictable auth marker signing fallback | `src/lib/supabase/auth-session.ts` falls back to a deterministic source literal when all configured secret candidates are absent. Could allow marker forgery in that configuration. | Require a strong independent server secret and fail closed when absent; test cookie tampering/rotation with config absent and present. |
| R2 | High | Live DB integration baseline fails | `npm test`: 288/289; the configured workspace query in the cross-device integration test fails. Live database state and isolation are therefore unverified. | Use isolated test project/database, apply migrations explicitly, diagnose safe error metadata, and keep credentials out of local generic test runs. |
| R3 | High | Local-first/server-backed state split | README and `RecallContext` show that many user changes remain browser-local while media/AI state is server-backed. New AI features can omit or use stale content. | Choose authoritative write/read contract and perform reconciliation/backfill before retrieval features. |
| R4 | High | Provider-specific schema parity | Supabase migrations/RLS, standalone PostgreSQL DDL, and MongoDB runtime indexes/transactions differ. A feature may work in one provider and fail in others. | Maintain a provider capability matrix and integration contract; test uniqueness, transactions, status updates, ownership and migrations on every supported provider. |
| R5 | High | RLS not present in standalone PostgreSQL DDL | `database/postgres/001_keeper.sql` has workspace columns and constraints but does not enable RLS. A future route/query omission can expose cross-tenant records. | Keep DB private and server-only; use restricted DB role and enforce workspace scoping in store/API; consider DB-level policies where operationally feasible. |
| R6 | High | Source text/media availability is not guaranteed | Instagram/LinkedIn/YouTube authorized media access varies; OCR/STT require configured services. Summaries/search can be absent or metadata-only. | Preserve stage-specific status and source provenance; test explicit restricted/partial cases; avoid presenting generated guesses as captured source. |
| R7 | High | Credentials in test path are loaded from local `.env.local` | `scripts/run-tests.ts` reads `.env.local` and may make live Supabase requests. Running generic suite can contact a developer/production project based on local configuration. | Separate and explicitly opt-in live integration test; require dedicated test-project assertion and never load `.env.local` automatically for the unit suite. |
| R8 | High | AI indexing can leak stale or cross-tenant content | Future embeddings/chunks/graph/recommendations introduce replicated data and deletion complexity. Current assistant passes bounded item candidates and scopes via routes, but no vector isolation mechanism exists. | Store workspace ID on every derived row, enforce tenant filters/RLS, recheck authorization, and cascade/reconcile deletes and reprocessing. |
| R9 | Medium | Bulk history and retry UI is not fully durable | Browser `ImportJobService` stores job/report data in localStorage; AI jobs are durable separately. A unified queue cannot simply reuse the local job record. | Persist import job/item history and make retries idempotent before Smart Inbox. |
| R10 | Medium | Current content fingerprint is not semantic similarity | SQL trigger hashes lowercased concatenated title/description/caption/body only when >=80 chars; exact hash index does not find near-duplicates. | Version algorithm, normalize fields safely, use candidate review and avoid destructive automatic merges. |
| R11 | Medium | Content preservation is incomplete | Transcripts and metadata persist, but checked schemas show no generalized source snapshot/blob storage/checksum or object lifecycle. Preview URL is not a retained asset. | Define preservation tiers, object-store interface, checksums, retention and deletion/export semantics. |
| R12 | Medium | Database schema drift/partial migrations | Supabase migration order includes incremental AI, conversation and webhook changes; standalone schema is a separate snapshot. Migration application state is not exposed in repository. | Keep migrations ordered, verify from clean disposable database for each release, and report applied version per deployment. |
| R13 | Medium | Open-source boundary still contains billing code | README says monetization/quotas removed, but Razorpay dependency, billing routes, webhook handler and billing DDL remain. May confuse deployment, expose unused surface, or create unintended provider coupling. | Verify edition route behavior and document residual compatibility; preserve paid functionality per scope while isolating provider requirements. |
| R14 | Medium | Compose has local sample credentials and mandatory Supabase Auth | Docker Compose includes example database password and service uses Supabase Auth config; “one command” needs operators to configure identity and replace sample credentials for non-local use. | Clarify first-run setup and require unique secrets for network-exposed deployment. |
| R15 | Medium | Lint warning debt | `npm run lint` passes with 255 warnings, including broad `any`, unused bindings, hook and navigation warnings. | Track warning ceiling/trend and address relevant files with each future feature; do not claim clean lint. |
| R16 | Medium | No build was run in this audit | Production build output can mutate `.next` and fetch fonts; deployment compile result is unknown for this checkout. | Run build in disposable/CI environment and capture exact current result before release. |
| R17 | Low/Medium | Search ranking is lexical and in-memory | `SearchService` has useful synonyms/fuzzy matching but no database FTS/vector indexes; scaling and relevance beyond local test corpus are unknown. | Keep current search as hybrid lexical baseline, build labeled evaluation corpus and measure latency/relevance before replacing. |
| R18 | Low/Medium | Re-discovery and learning lack feedback/progress models | Existing activity is basic SavedItem metadata/favorite and collection corrections; no recommendation feedback or learner progress tables exist. | Add explicit opt-in event/progress data models and lifecycle/retention before model features. |

Severity describes plausible impact from source inspection, not a confirmed exploitation or production incident. External environment and runtime deployment checks were unavailable.
